## New: `--font-slug`

The renderer fetches fonts and layouts from the font repo instead of carrying
its own:

```bash
node render.mjs song.mp3 song.lrc --font-slug ams-manthan
```

Resolves `.ttf` + `layouts/<slug>.json` together, reads the family name out of
the font file, and fails loudly if either is missing. `--fonts-repo <dir>`
overrides the location; otherwise it looks for a sibling
`nepali-legacy-fonts`.

A missing layout is a **hard error**, not a fallback to Preeti. That fallback
was the original trap: feed a Preeti-era map to a font that doesn't speak it and
you get collapsed glyphs and a literal `==` where the danda should be — no
error, just wrong output.

Verified: happy path resolves and prepares; `--font-slug no-such-font` exits 1
naming the exact path it looked for.

## New: `check_song.py` (font repo)

The check that would have saved an hour. `verify_layouts.py` asks whether a
layout's keys reach real glyphs. `check_song.py` asks whether a layout can write
*this song*. Both can be true and still fail:

```
py scripts/check_song.py --font ams-manthan song.lrc
py scripts/check_song.py --font x --all song.lrc     # all 79
py scripts/check_song.py --word "फर्केर" --font ams-manthan
```

Exit 0 = every line survives, 1 = some do not, so it gates a render in a script.

On Allare: **0 of 79 layouts can write it.** Two characters are the entire
cause — `U+094D` virama and `U+0901` candrabindu — and aNepali publishes
neither as a key, so no generated layout can contain them.

### The part worth remembering

The virama is not a missing diacritic. It's the instruction that fuses a
conjunct. Drop it and one character becomes two letters, so `फर्केर` renders as
`फरकर` — a **different word**, set perfectly, for several seconds. The candrabindu
is gentler: `सँगै` → `संगै` changes the spelling, usually not the word.

Nothing downstream catches either. The render exits 0, is the right length, has
a pure-black background, passes every output check — because every check looks
at the container, the timing, or the pixels *behind* the text, and none of them
look at the text. Full write-up in [SONG-CHECK.md](SONG-CHECK.md).

## Bugs found while building `check_song.py`

All three produced a confident wrong answer rather than an error, which is why
they're worth writing down:

1. Requiring every layout map value to be length 1 rejects the *real* map (some
   keys emit a two-character sequence). Result: empty map, 100% failure score
   on a song that's 57% fine.
2. Testing keys instead of values asks "is `ा` a key" — never true — so the
   whole script reads as unwritable.
3. Collecting affected words against running totals flagged every word on every
   failing line: 40 words reported where there are 16.
